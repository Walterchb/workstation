Instalar y usar Jornada

Probar en Windows

Haz clic derecho sobre el ZIP, elige Extraer todo y abre la carpeta que contiene index.html. Ábrelo con Edge o Chrome para explorar la demostración. Puedes editar sus actividades ficticias y recorrer las tres vistas.

La demostración guarda sus cambios en el navegador. Tu cuenta de Supabase comienza vacía y guarda tus registros en la nube. Usa esa cuenta cuando empieces a anotar trabajo real.

1. Preparar la base de datos

  1. Entra al panel de Supabase, selecciona tu organización y haz clic en New project. Elige un nombre como jornada-personal, la región disponible que prefieras y una contraseña para la base. Guárdala en tu gestor de contraseñas.
  2. Cuando el proyecto esté listo, abre SQL Editor en la barra lateral. Inicia una consulta con New query o el botón +.
  3. En la carpeta extraída, abre supabase/schema.sql con el Bloc de notas. Selecciona todo con Ctrl + A, copia y pega el contenido completo en la consulta. Pulsa Run.
  4. Espera el mensaje de éxito. En el esquema jornada_private se crea la tabla agendas. Cada fila pertenece a una cuenta. En public quedan las funciones de lectura y guardado. El script configura los permisos y activa la seguridad por fila (RLS).

Si elegiste las opciones estándar de un proyecto nuevo, el esquema public está disponible para la Data API. Si personalizaste el proyecto, verifica que la API esté habilitada y que public figure en sus esquemas expuestos. jornada_private debe permanecer privado.

2. Crear tu acceso personal

  1. Abre Authentication → Sign In / Providers. Comprueba que el proveedor Email esté habilitado. En la configuración de altas, desactiva Allow new users to sign up y guarda. Así, tú decides desde el panel a quién crearle una cuenta.
  2. Ve a Authentication → Users → Add user → Create new user. Ingresa tu correo y elige la contraseña que usarás en Jornada.
  3. Marca Auto confirm user? y pulsa Create user. Esta opción confirma directamente la cuenta que estás creando. Verifica que tu correo aparezca en la lista de usuarios.

La contraseña de la base permite administrar PostgreSQL. Para el formulario de Jornada usa el correo y la contraseña creados en este paso.

3. Conectar Jornada con Supabase

  1. En la parte superior del proyecto, abre Connect y copia la Project URL. Tiene el formato https://tu-proyecto.supabase.co.
  2. Copia la Publishable key, que comienza con sb_publishable_. También puedes encontrarla en Settings → API Keys. Los proyectos antiguos pueden ofrecer una clave pública anon. Para un proyecto nuevo elige la clave publicable.
  3. En tu carpeta extraída, haz clic derecho en config.js y elige Abrir con → Bloc de notas. Sustituye los campos vacíos con los dos valores de tu proyecto, entre las comillas existentes. Guarda con Ctrl + S.
window.JORNADA_CONFIG = {
  supabaseUrl: "https://TU-PROYECTO.supabase.co",
  supabasePublishableKey: "sb_publishable_TU_CLAVE"
};

Ambos textos son ejemplos. Pega los valores que copiaste del mismo proyecto. El navegador puede ver este archivo. Jornada conecta directamente con Supabase y carga la tipografía desde los archivos del sitio. Conserva la contraseña y las claves de servidor sb_secret_… y service_role exclusivamente en tus herramientas de administración.

4. Publicar el sitio en GitHub Pages

  1. En GitHub → New repository, crea un repositorio aparte con el nombre jornada-personal. Para usar Pages con GitHub Free personal, selecciona Public. Si tu plan admite Pages en repositorios privados, también puedes seleccionar Private. El sitio publicado puede ser accesible en internet incluso con el código en un repositorio privado. Los datos de tu agenda viven en Supabase.
  2. En el repositorio vacío, pulsa uploading an existing file. Si ya tiene un archivo, pulsa Add file → Upload files. Vuelve al Explorador de Windows y entra hasta ver index.html. Selecciona todo el contenido de esa carpeta y arrástralo a la página de GitHub. Conserva la estructura original.
  3. Pulsa Commit changes para guardar en main. Al abrir la pestaña Code, debes ver index.html y config.js al mismo nivel que las carpetas assets/ y supabase/. Si ves el ZIP o una sola carpeta contenedora, vuelve a cargar los archivos desde la carpeta que contiene index.html.
  4. Abre Settings → Pages → Build and deployment. En Source, selecciona Deploy from a branch. Elige main, /(root) y Save. Si creaste el repositorio con otro nombre de rama, elige la rama que contiene tus archivos.
  5. Consulta el avance en Actions. Una vez publicado, vuelve a Settings → Pages y abre Visit site. La dirección del ejemplo es https://TU-USUARIO.github.io/jornada-personal/. Guarda la dirección real en tus favoritos.

Si quieres dejar configurados los enlaces de autenticación del proyecto, copia la URL publicada con su carpeta de repositorio en Authentication → URL Configuration → Site URL de Supabase. El inicio directo por contraseña funciona sin redirecciones.

5. Comprobar que tu agenda quedó conectada

  1. Abre el sitio publicado. Debe aparecer el inicio de sesión. Ingresa con la cuenta que creaste en Supabase.
  2. En Mi jornada, selecciona la fecha de hoy y crea una actividad llamada «Prueba de guardado». Guarda la actividad.
  3. Cierra sesión y abre el sitio en una ventana privada o en tu teléfono. Entra con la misma cuenta y selecciona la misma fecha. Debes encontrar «Prueba de guardado».
  4. Para comprobar el aislamiento entre cuentas, crea una segunda cuenta de prueba desde Authentication → Users. Abre una ventana privada nueva, entra con ella y verifica que la agenda está vacía. La primera cuenta debe seguir conservando su actividad.

La sesión se guarda en la pestaña actual. Cuando la cierres, vuelve a entrar con tu correo para recuperar lo que guardaste en Supabase.

Registrar tu día de trabajo

Antes de las 08:00

En Mi jornada, abre Agregar actividad y elige Entrada rápida. Escribe la actividad, pulsa Tab para completar el contexto y luego Enter para añadirla y seguir con la próxima. Para los reportes habituales, elige Reutilizar, selecciona un día anterior y trae varias tareas como pendientes nuevas. Si el encargo surgió durante el día, selecciona Imprevista antes de guardarlo. Si varias contribuyen a un mismo resultado, créalo en Objetivos y vincúlalas a él. Por ejemplo, «Responder observaciones del due diligence» puede contribuir al objetivo «Emitir bonos corporativos». Si la actividad sigue otro día, abre su ficha, pulsa Continuar otro día y elige la fecha. El trabajo de hoy conserva sus horas y su comentario.

Al empezar y al cambiar de actividad

La lista agrupa las actividades en proceso, pendientes y culminadas. Pulsa el nombre de un grupo para plegarlo o desplegarlo. El selector de orden también permite ver la secuencia de tu plan o dar prioridad a las tareas altas.

Usa Iniciar cuando empieces y Pausar al cambiar de tarea. Para registrar o corregir la hora a mano, abre el lápiz de la actividad. Si la retomas, abre otro tramo en la misma actividad. Las 08:00 sirven de referencia para leer el día. La aplicación suma los tramos cerrados que registraste y deja libres las pausas.

Al cerrar la jornada

Marca si cumpliste el avance previsto para hoy. Puedes dejar el encargo En proceso y escribir «Se respondió la última observación y se remitió el texto para validación». Cuando se concrete la emisión, anota el resultado y su fecha en Objetivos. En Análisis elige el período que quieres explicar a gerencia y revisa la distribución de horas por objetivo o por categoría junto con la evidencia del avance. Pulsa Informe gerencial y elige Guardar como PDF en el cuadro de impresión. Con Exportar CSV obtienes el detalle por tramo para Excel. Para sumar actividades usa la columna «Conteo de actividades» y para las horas, «Minutos cerrados» dividido entre 60.

Resolver problemas frecuentes

Se sigue abriendo la demostración
En GitHub abre config.js y comprueba que ambos valores reales estén guardados. Revisa el último despliegue de Pages, abre la URL publicada y actualiza con Ctrl + F5.
La configuración aparece incompleta
Completa ambos campos del archivo con los valores del mismo proyecto. Conserva las comillas, la coma y el nombre exacto config.js. Sube el cambio y espera a que se publique.
GitHub muestra 404 o faltan los estilos
Abre la dirección de Visit site. Revisa que la fuente sea la rama correcta y /(root), que index.html esté en la raíz y que la carpeta assets/ conserve su nombre y sus archivos.
El formulario rechaza el correo o la contraseña
Verifica el correo en Authentication → Users, su confirmación y que el proveedor Email esté activo. Comprueba que hayas usado la contraseña de esa cuenta y la URL de ese mismo proyecto.
La cuenta inicia, pero aparece un error al leer o guardar
Revisa tu conexión y que el proyecto de Supabase esté activo. Comprueba el resultado de schema.sql en SQL Editor y, si quedó incompleto, vuelve a ejecutar el archivo completo. Revisa en la configuración de la Data API que el esquema public esté expuesto.
Otra sesión modificó la agenda mientras editabas
Copia el texto que estabas escribiendo antes de actualizar. Recarga la página, comprueba qué llegó del otro dispositivo y vuelve a aplicar tu cambio sobre la información actual.
